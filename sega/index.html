Summary

Geospatial algorithms have been improved by hand: a researcher spots a limitation, proposes a fix and tests it. SEGA (Self-Evolving Geospatial Algorithms) lets LLM agents take over much of this inner loop of generating, testing and selecting algorithm variants, while the researcher defines the question, the objective and the evaluation. It combines a two-loop evolution engine that retrieves geographic knowledge every round, an automatic code formatter that prepares any seed algorithm for evolution, and a simulation-driven protocol that evolves only on synthetic data with known ground truth, so that results on real data stay out of sample. In a case study on spatial regime discovery, the evolved algorithm recovers planted regimes better than its seed and four classical regionalization methods on 150 simulated grids, and transfers unchanged to 11 real-world datasets.

The SEGA framework

Three modules, marked 1 to 3 in the diagram.

1Evolution engine

A two-loop engine. The inner loop mutates and selects code. After each round, an outer loop analyzes the best program, retrieves geographic knowledge for the gaps it finds, and rewrites the prompt of the next round.

2Code formatter

LLM chains turn a raw seed algorithm into the standardized input the engine needs: an evolvable program, an evaluator and a configuration. The evolved code is returned in the same form.

3Simulation-driven protocol

Evolution sees only synthetic data with a known ground truth. The best algorithm is then frozen and applied unchanged to real data, which it never saw during the search.

Case study: evolving a spatial regime algorithm

Spatial regime discovery partitions a study area into contiguous regions, each with its own regression relationship. Starting from Two-stage K-Models, SEGA ran 10 rounds of 10 iterations. The fitness was the Rand Index against the planted partition, averaged over three training grids; candidates never see that partition.
